# О программе Mustash

«Mustash» расшифровывается как Music Streaming Assistant Hub. Это серверное приложение для автоматизации Spotify через Web API. В текущей версии основной сценарий - создание автоматических плейлистов («автоплейлистов») на основе песен, сохранённых у вас в списке избранного (они же `Liked Songs`, они же `Saved Tracks`).

Проект рассчитан на личное использование: вы запускаете его локально или в облачном сервере, авторизуете свой Spotify-аккаунт и дальше приложение само поддерживает нужные плейлисты в актуальном состоянии.

## Что умеет приложение

- Создавать и обновлять плейлисты из последних сохраненных треков по указанному их количеству.
- Создавать и обновлять плейлисты по годам сохранения.
- Создавать и обновлять сборные плейлисты - объединение нескольких существующих плейлистов в один.

Для создаваемых плейлистов будут генерироваться обложки. 

Дополнительно, есть функция, которая будет выводить в логах трек, который играет в данный момент.

## Требования

- Для работы приложения нужен платный Spotify-аккаунт.
- Для запуска нужен Node.js и npm.
- Для запуска в контейнере - Docker и Docker Compose.

## Настройка Spotify App

1. Создайте приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Сохраните `Client ID` и `Client Secret`.
3. Добавьте `Redirect URI` для OAuth (можно несколько). Для локального запуска например `http://127.0.0.1:3000/callback`. Для запуска на сервере - нужный домен (просто ip-адрес не подойдет)
4. Сохраните изменения.

При первой авторизации приложение может запросить такие scopes:

- `user-read-currently-playing`
- `user-library-read`
- `ugc-image-upload`
- `playlist-modify-private`
- `playlist-read-private`
- `playlist-read-collaborative`

## Переменные окружения

Конфигурация хранится в `.env`. Можно взять один из шаблонов:

- `.env.minimal.example` - минимальный набор для автоплейлистов;
- `.env.full.example` - полный набор со всеми поддерживаемыми параметрами.

Основные параметры:

- `APP_LOCALE` - язык логов: `EN` или `RU`.
- `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` - доступ к Spotify API.
- `SPOTIFY_REDIRECT_URI` - callback URL для OAuth.
- `SPOTIFY_PROXY_URL` - прокси для доступа к Spotify API, если прямое соединение недоступно.
- `SAVED_RECENT_WINDOWS` - список размеров плейлистов последних треков через запятую, например `50,200,500`.
- `SAVED_IN_YEAR_YEARS` - список годов для годовых автоплейлистов.
- `AUTO_PLAYLISTS_MERGED_PLAYLISTS` - сборные плейлисты (см. раздел «Сборные плейлисты» ниже).
- `AUTO_PLAYLISTS_RECENT_FROM_PLAYLISTS` - автоплейлисты из первых N треков указанных плейлистов (см. раздел «Первые N треков плейлиста» ниже).
- `TRACK_MONITORING_ENABLED` - включение логирования текущего трека.
- `AUTO_PLAYLISTS_PLAYLIST_PREFIX` и `AUTO_PLAYLISTS_PLAYLIST_SUFFIX` - оформление имен плейлистов.
- `SAVED_RECENT_COVER_COLOR`, `SAVED_IN_YEAR_COVER_COLOR`, `RECENT_FROM_PLAYLISTS_COVER_COLOR` - цвета обложек в формате HEX без `#`.
- `AUTO_PLAYLISTS_FREQUENT_SYNC_INTERVAL_MS` - интервал обновления recent-плейлистов.
- `AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS` - интервал обновления year-плейлистов.
- `AUTO_PLAYLISTS_SYNC_QUEUE_GAP_MS` - обязательная пауза между циклами синхронизации в общей очереди.
- `POLL_INTERVAL_MS` - интервал проверки текущего трека.
- `SPOTIFY_MIN_REQUEST_GAP_MS` - минимальная пауза между запросами к Spotify API.

Если `DATABASE_URL` не задан, приложение продолжит работу без функций, зависящих от БД. В этом режиме OAuth-токены и runtime state сохраняются локально в `temp/app-state.json`.

Минимальный пример:

```env
SPOTIFY_CLIENT_ID=your_client_id
SPOTIFY_CLIENT_SECRET=your_client_secret
SPOTIFY_REDIRECT_URI=http://127.0.0.1:3000/callback

SAVED_RECENT_WINDOWS=50,200
SAVED_IN_YEAR_YEARS=2024,2025
```

Полный пример:

```env
APP_LOCALE=RU

SPOTIFY_CLIENT_ID=your_client_id
SPOTIFY_CLIENT_SECRET=your_client_secret
SPOTIFY_REDIRECT_URI=http://127.0.0.1:3000/callback

SPOTIFY_PROXY_URL=
DATABASE_URL=

SAVED_RECENT_WINDOWS=50,200
SAVED_IN_YEAR_YEARS=2024,2025
AUTO_PLAYLISTS_MERGED_PLAYLISTS=
AUTO_PLAYLISTS_RECENT_FROM_PLAYLISTS=
TRACK_MONITORING_ENABLED=true

AUTO_PLAYLISTS_PLAYLIST_PREFIX=
AUTO_PLAYLISTS_PLAYLIST_SUFFIX=[AUTO]
SAVED_RECENT_COVER_COLOR=000000
SAVED_IN_YEAR_COVER_COLOR=060E73
RECENT_FROM_PLAYLISTS_COVER_COLOR=14532D

AUTO_PLAYLISTS_FREQUENT_SYNC_INTERVAL_MS=600000
AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS=10800000
AUTO_PLAYLISTS_SYNC_QUEUE_GAP_MS=60000
POLL_INTERVAL_MS=5000
SPOTIFY_MIN_REQUEST_GAP_MS=500
```

## Сборные плейлисты

Переменная `AUTO_PLAYLISTS_MERGED_PLAYLISTS` позволяет объединить несколько существующих плейлистов в один новый, который приложение будет автоматически поддерживать в актуальном состоянии.

Формат: `Целевой=Источник1+Источник2`, несколько сборных разделяются `;`:

```env
AUTO_PLAYLISTS_MERGED_PLAYLISTS=Мой Мегамикс=RECENT 50 [AUTO]+2024 [AUTO];Тренировка=Gym Beats
```

Как это работает:

- Имена источников ищутся среди ваших плейлистов по точному совпадению (если источники - автоплейлисты этого приложения, указывайте их имя вместе с префиксом/суффиксом).
- К имени целевого плейлиста применяются те же `AUTO_PLAYLISTS_PLAYLIST_PREFIX` и `AUTO_PLAYLISTS_PLAYLIST_SUFFIX`, что и к остальным автоплейлистам. Плейлист создаётся автоматически, если его ещё нет.
- Треки всех источников собираются вместе, сортируются по дате добавления в исходные плейлисты (свежие сверху) и дедуплицируются - повторяющиеся треки остаются только один раз. Если трек встречается в нескольких источниках, его позицией считается самая ранняя дата добавления среди всех вхождений.
- Обновление выполняется вместе с годовыми плейлистами, раз в `AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS`.
- Если какой-то плейлист-источник не найден или недоступен (например, ошибка доступа), он пропускается (в логе будет предупреждение), остальные источники обрабатываются.
- Переменная необязательна: если она не задана, сборные плейлисты не создаются.

## Первые N треков плейлиста

Переменная `AUTO_PLAYLISTS_RECENT_FROM_PLAYLISTS` создаёт автоплейлисты из первых N треков указанного плейлиста (верхушки плейлиста, в его текущем порядке) - по аналогии с recent-плейлистами из сохранённого, но источником служит конкретный плейлист.

Формат: `Источник:50,100`, несколько источников разделяются `;`:

```env
AUTO_PLAYLISTS_RECENT_FROM_PLAYLISTS=Hard Rock:50,100;Gym Beats:30
```

Как это работает:

- Для каждого источника и каждого размера окна создаётся отдельный автоплейлист с автоматическим именем вида `Hard Rock 50 [AUTO]`, `Hard Rock 100 [AUTO]` (применяются те же `AUTO_PLAYLISTS_PLAYLIST_PREFIX` и `AUTO_PLAYLISTS_PLAYLIST_SUFFIX`, что и у остальных автоплейлистов).
- «Первые N треков» - верхняя часть плейлиста-источника в его текущем порядке. Повторяющиеся треки остаются только один раз. Удобно для плейлистов, поддерживаемых самим приложением (сборные пишутся «свежие сверху»), и для любых плейлистов, порядок в которых вы контролируете вручную.
- Плейлист-источник ищется по точному совпадению имени. Если источник не найден, автоплейлисты этого источника пропускаются до следующей синхронизации (в логе будет предупреждение).
- Обновление выполняется вместе с годовыми и сборными плейлистами, раз в `AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS`.
- Цвет обложки настраивается переменной `RECENT_FROM_PLAYLISTS_COVER_COLOR` (по умолчанию `14532D`).
- Переменная необязательна: если она не задана, такие автоплейлисты не создаются.
- Ограничение: имена источников с `;` или `:` внутри не поддерживаются (разделители).

## Циклы синхронизации и общая очередь

Обновление автоплейлистов выполняется тремя независимыми циклами:

- **частый** - recent-плейлисты, интервал `AUTO_PLAYLISTS_FREQUENT_SYNC_INTERVAL_MS` (по умолчанию 10 минут);
- **редкий** - годовые плейлисты (и архив удалённых треков, если подключена БД), интервал `AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS` (по умолчанию 3 часа);
- **сборный** - сборные плейлисты и плейлисты «первые N треков плейлиста», обновляется вместе с редким по `AUTO_PLAYLISTS_RARE_SYNC_INTERVAL_MS`.

Все циклы проходят через одну общую очередь, поэтому одновременно всегда выполняется не более одного цикла - они не пересекаются, даже если таймеры сработали одновременно. При старте приложения первый цикл каждого сервиса стартует сразу и выстраивается по очереди: частый → редкий → сборный.

Между последовательными циклами очередь выдерживает обязательную паузу `AUTO_PLAYLISTS_SYNC_QUEUE_GAP_MS` (по умолчанию 1 минута) - это страховка от rate limit Spotify API. Пауза не задерживает завершившийся цикл: его результат и лог «цикл завершён» появляются сразу, а ждёт паузу только следующий цикл в очереди. В логах это видно как разрыв по времени между завершением одного цикла и стартом следующего.

## Локальный запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env` на основе одного из шаблонов и заполните обязательные параметры.

3. Для запуска в дев-режиме

```bash
npm run dev
```

ИЛИ

3. Для запуска в прод-режиме:

```bash
npm run build
npm run start
```

## Запуск через Docker Compose

```bash
docker-compose up -d
docker-compose logs -f
```

ИЛИ

```bash
docker-compose up
```

Compose передает переменные окружения в контейнер из корневого `.env`. Для Docker используются те же параметры приложения, что и для локального запуска.

## Что произойдет при первом старте

После запуска приложение:

1. выведет в лог загруженную конфигурацию;
2. попросит пройти OAuth-авторизацию Spotify;
3. сохранит токены;
4. начнет циклы обновления автоплейлистов;
5. при включенном мониторинге начнет писать в логи текущий трек.

Обычно сценарий такой:

- открываете URL, который приложение пишет в лог;
- подтверждаете доступ в Spotify;
- возвращаетесь к логам и проверяете, что началось создание или обновление плейлистов.


## Ограничения и замечания

- Приложение использует polling, а не webhooks.
- Многопользовательский сценарий не является основным.
- Spotify API может ограничивать запросы по rate limit.
- Если у вас российский IP, для доступа к Spotify API может понадобиться прокси, который нужно прописать в `SPOTIFY_PROXY_URL`.
- Не запускайте сразу несколько копий приложения на одном и том же Spotify-аккаунте без необходимости.

## Безопасность

- Не коммитьте `.env`.
- Не публикуйте `SPOTIFY_CLIENT_SECRET`.
- Запускайте приложение только в доверенном окружении.
